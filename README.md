# QuickFixers

Repair-service platform: **clients** create tickets for a service, **support** agents fix them, and the **admin** manages everything (users, roles, services, payments, revenue).

Three roles, modeled as one JPA inheritance chain (`Person` → `Admin` / `Support` / `Client`):

| Role | What they do |
|---|---|
| **CLIENT** | Create tickets, view details, **pay** their tickets, browse services |
| **SUPPORT** | Fix tickets assigned to them, change ticket status, view related payments |
| **ADMIN** | Everything: users, roles, services, tickets, payments, revenue stats |

Monorepo containing two independent projects:

| Project | Stack | Port | Docs |
|---|---|---|---|
| 📦 `QuickFixersBackend` | Spring Boot REST API (Java 21, MySQL, JWT, Flyway, OpenPDF) | 8081 | [Backend README](QuickFixersBackend/README.md) |
| 📦 `QuickFixersFrontend` | React + Vite SPA (Tailwind 4, React Router 7, Axios) | 5173 | [Frontend README](QuickFixersFrontend/README.md) |

## 🚀 Quick start

> Detailed steps live in each project's own README — this is just the order of operations.

1. **Start MySQL** on `localhost:3307` (the app creates `QuickFixers_db` and runs the Flyway migrations automatically).
2. **Start the backend** — from `QuickFixersBackend/`:
   ```bash
   .\mvnw.cmd spring-boot:run
   ```
   API ready at `http://localhost:8081/api` (Swagger UI: `http://localhost:8081/swagger-ui/index.html`).
3. **Start the frontend** — from `QuickFixersFrontend/`:
   ```bash
   npm install
   npm run dev
   ```
   Open `http://localhost:5173`, register a **CLIENT** account or log in with an existing one.

## 💳 Payments & receipts

- A client pays a ticket from its **details page** (`/user/tickets/:id`). The button only appears when the ticket is not yet `FERME` and its service has a price. Paying marks the payment `TERMINE` and closes the ticket.
- After paying, the transaction appears in **"Mes paiements"** (`/user/payments`) with a **"Télécharger le reçu"** button → downloads a small PDF receipt (A6) generated by the backend (`GET /api/paiements/recu/{id}`).

---

## ✉️ Account-creation email

When an account is created — a client registering, or an admin adding a user/support in **Utilisateurs** — the backend sends an email with the account info (role + plain password). The email is optional: if it fails, the account is still created.

---

## 🔐 Users & roles (admin)

- Only **ADMIN** can edit a user (name/email) or change a role (page **Utilisateurs**, or the dedicated **Clients** / **Supports** pages).
- Role changes are restricted to **CLIENT ⇄ SUPPORT** — an administrator can never be modified.
- Switching a user to **SUPPORT** requires their **service type** (specialty): ELECTRONIQUE, ELECTROMENAGER, INFORMATIQUE, TELEPHONIE. The UI asks for it before confirming the change.
